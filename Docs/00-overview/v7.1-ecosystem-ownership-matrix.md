# v7.1 Ecosystem Ownership Matrix

Status: audit baseline — M1 design authority

Last review: 2026-07-15

## Scope, method, and classification

This is the single ownership decision record for v7.1 snapshot work. It covers
state surfaces statically referenced by the current Kitsunping, KitsunpingApp,
and KitsunpingRouter source trees, plus Android/vendor and router boundaries
reached by those components. It is not a claim that every optional path exists
on every device or router.

The existing categories are sufficient. An item may have multiple labels where
the labels describe different dimensions: `secret` + `credential` +
`pairing_state`, for example. No new category is required.

| Label | Meaning for this matrix |
| --- | --- |
| `module_config` | A declared Kitsunping preference with a stable, validated contract. |
| `module_runtime` | Live state, command, lock, sequence, or process coordination. |
| `module_derived` | A result recalculated from configuration and observed environment. |
| `legacy_compat` | A non-canonical alias retained only to read/migrate old state. |
| `external_readonly` | Data owned by Android, vendor, carrier, or router and consumed only as input. |
| `external_managed` | An external setting the existing installer/profile flow may change with its own rollback. |
| `secret` | Value that must not be disclosed or serialized in an ordinary snapshot. |
| `credential` | Value that authenticates or authorizes a party. |
| `pairing_state` | Binding state whose validity depends on both phone and router. |
| `cache` | Regenerable/expirable local material, never ordinary snapshot input. |
| `telemetry` | Diagnostics, measurements, events, counters, or logs. |

`Snapshot` below means the v7.1 normal module-configuration snapshot only. It
does **not** mean the legacy installer original-property backup, an Android app
backup, a full-device backup, or a router backup.

## Boundary ownership rules

| Boundary | Owner | Permitted writers | Permitted readers | Snapshot rule |
| --- | --- | --- | --- | --- |
| Module canonical configuration | Kitsunping | Explicit user/app control only after allowlist validation; installer defaults | module runtime; app may read declared keys | Candidate only after an M1 validator exists. |
| Module runtime/cache | Kitsunping daemon/executor | daemon, executor, service; app only where explicitly documented | app diagnostics and module runtime | Never serialize; remove or regenerate after restore. |
| Android app private storage | KitsunpingApp | app process only | app process only | Out of scope for v7.1 normal snapshots. |
| Router session and QoS runtime | KitsunpingRouter/router administrator | router agent or admin action | router agent/status UI | Never read, modify, export, or restore from a phone snapshot. |
| Android/vendor/carrier state | Android, vendor, carrier | platform/vendor only except existing isolated module actions | module diagnostics | Never snapshot. |

## Router lifecycle and post-restore convergence

A normal v7.1 restore has exactly one permitted router result when the snapshot
contains no currently validated authenticated session:

> **Router enabled but requires re-pairing.**

The state is not ambiguous. `persist.kitsunrouter.enable` may reflect the
restored user preference. `persist.kitsunrouter.paired` is forced to `0`, and no
router-authenticated operation is permitted until new pairing completes.

Required sequence for the later live-restore milestone:

1. Acquire the module single-writer lock and stop/coordinate daemon, executor,
   calibration, target-policy writes, and router status push.
2. Validate/stage normal snapshot data. It contains only approved canonical
   `module_config` keys.
3. Before applying configuration, delete module pairing credentials and all
   router discovery/push caches: `router.pairing.json`, `router.last`,
   `router.dni`, `router_*.info`, `router.status.*`, `router.push.*`, router
   channel cache/state and pairing state.
4. Clear `persist.kitsunrouter.paired` to `0`; clear both app-command property
   spellings; clear all runtime locks/PIDs/requests/derived policy/calibration
   state listed in Matrix B.
5. Coordinate with KitsunpingApp to clear `kitsunrouter_pairing`, including
   token, endpoint, router ID, paired flag, and sequence. If that coordination
   cannot be proven, **abort restore** rather than leaving two state stores in
disagreement.
6. Apply/read-back only the validated canonical configuration values. Do not
   touch Android/vendor settings, router filesystem, app UI data, package rules,
   model files, logs, or legacy original-property backup.
7. Restart/resume runtime. It regenerates current network context, discovery,
   calibration eligibility, policy state and cache from current observations.
8. App reads the resulting unpaired state and offers explicit QR/code pairing.
   A new router token/session is obtained only from the router after validation.

The router may still have a server-side historical entry for this device. The
phone must neither assume it is valid nor replay its token/sequence. Normal
router TTL/sweep/revocation controls remain router-owned. This intentionally
avoids a phone snapshot acting as a router administration request.

## M1 blockers and required decisions

M1 is permitted to implement a parser and isolated temporary-directory
validation only. It must not create a production allowlist or live restore
until these blockers are resolved in the matrix source used by code:

1. **Canonical aliases:** define canonical key, precedence, owner, validator and
   alias behavior for every duplicate `persist.*`/non-persistent property family.
2. **Uncontracted keys:** `daemon.adaptive_*`, `daemon_trace`, `dev_score_*`,
   `qos.*`, ONNX controls and any dynamically discovered key remain rejected.
3. **Router two-store convergence:** prove an atomic app/module clear protocol
   for `kitsunrouter_pairing`, `router.pairing.json`, and `paired=0`. The
   current app writes both stores and the daemon can synchronize the property
   from the file; a partial clear could reassert paired state.
4. **Target-policy replica:** package names live in app preferences and
   `target.prop`/`target.model.json`. The current snapshot contract excludes
   package lists, so normal M1 snapshots must leave them out. Future migration
   needs its own privacy choice and canonical source.
5. **Live writer contract:** no restore may proceed while a calibration,
   target-policy sync, pairing, router push, or daemon writer is active unless
   the lock/acknowledgement protocol is implemented and tested.
6. **Router correctness evidence:** the router audit documents a possible
   `sweep`/`revoke` mismatch with nft rules. No restore design may rely on
   router-side cleanup as an immediate security or QoS guarantee.

## Audit acceptance checklist

A later M1 implementation is conformant only if its source allowlist is a
machine-readable projection of the allowed Matrix A entries, and tests prove:

- unknown properties, aliases, all path-like values, pairing state, secrets,
  credentials, package lists, caches, logs and external values are rejected;
- only the explicit export surface is serialized;
- restore leaves router state exactly **enabled but requires re-pairing**;
- all Matrix B caches are discarded/regenerated rather than copied;
- app/module pairing stores converge to an unpaired state or restore aborts;
- no Android/vendor/router file or property is modified by snapshot code.
